AgentCore Workshop TelcoCare

Lab 1 · Runtime

Crei l'agente TelcoCare, lo provi sul tuo ambiente e lo pubblichi su AgentCore Runtime. Venticinque minuti.

Concetto: AgentCore Runtime

Runtime esegue il codice del tuo agente senza che tu gestisca server o container. Qui usiamo il deploy di tipo CodeZip: il CLI impacchetta il codice Python con le sue dipendenze e lo carica, senza Docker.

Ogni conversazione ha un ID di sessione. Ogni sessione gira in una microVM isolata, che resta viva per le richieste successive della stessa sessione. Una sessione nuova parte da una microVM nuova.

  1. Crea il progetto dal modello Strands in Python. L'opzione --skip-git evita di creare un repository git dentro quello del workshop.

    cd ~/agentcore-workshop
agentcore create --name TelcoCare --template agent-python-strands --skip-git
cd TelcoCare
    Cosa dovresti vedere 
    creating project tree
installing CDK dependencies with npm
syncing Python dependencies with uv
created project 'TelcoCare' in ./TelcoCare
    Ci vuole circa mezzo minuto. Da qui in poi tutti i comandi partono dalla cartella ~/agentcore-workshop/TelcoCare.

  2. Guarda cosa ha creato il CLI.

    PercorsoContenuto
    app/agent/main.pyIl codice dell'agente: modello, strumenti e punto di ingresso @app.entrypoint
    app/agent/model/load.pyIl modello Bedrock usato dall'agente
    agentcore/agentcore.jsonL'elenco delle risorse AgentCore del progetto. È il file che il CLI modifica quando aggiungi qualcosa
    agentcore/cdk/L'applicazione AWS CDK che trasforma agentcore.json in uno stack CloudFormation
    cat agentcore/agentcore.json

    Il modello del progetto dichiara già un Runtime (agent) e una Memory (agentMemory).

  3. Togli la Memory. La aggiungiamo nel Lab 2, così vedi la differenza fra un agente con e senza memoria.

    agentcore remove memory --name agentMemory

    Il codice del modello controlla la variabile MEMORY_AGENTMEMORY_ID: se non c'è, l'agente funziona senza memoria.

  4. Sostituisci main.py con la versione TelcoCare.

    cp ../risorse/lab1/main.py app/agent/main.py

    Rispetto al modello cambiano due cose: il prompt di sistema in italiano e uno strumento locale, calcola_rata. Uno strumento Strands è una funzione Python con il decoratore @tool: il modello legge la docstring per capire quando usarlo.

    app/agent/main.py (estratto)
    @tool
def calcola_rata(prezzo_euro: float, mesi: int) -> str:
    """Calcola la rata mensile per l'acquisto a rate di uno smartphone, senza interessi.

    Args:
        prezzo_euro: prezzo totale del dispositivo in euro
        mesi: numero di rate mensili (da 1 a 48)
    """
    if mesi < 1 or mesi > 48:
        return "Il numero di rate deve essere compreso fra 1 e 48."
    return f"{mesi} rate da {prezzo_euro / mesi:.2f} euro al mese"

  5. Avvia l'agente in locale. Il server si ricarica da solo quando modifichi i file.

    agentcore dev --port 8181
    Attenzione La porta predefinita di agentcore dev è la 8080, ma nel tuo ambiente la usa già Code Editor. Se lanci agentcore dev senza --port, la domanda arriva a Code Editor e ricevi {"error":"Unauthorized"} con status=401. Usa sempre --port 8181: chiedi.py --locale chiama già quella porta.

    Aspetta la riga Agent 'agent' is running on port 8181, poi apri un secondo terminale e fai una domanda all'agente locale.

    cd ~/agentcore-workshop/TelcoCare
python3 ../scripts/chiedi.py --locale "Vorrei uno smartphone da 899 euro in 30 rate. Quanto pago al mese?"

    Lo script chiedi.py costruisce il payload JSON, stampa il comando agentcore invoke che esegue e rende leggibile la risposta, che arriva in streaming.

    Cosa dovresti vedere Una risposta simile a questa. Il testo cambia da una prova all'altra, i numeri dei token pure. 
    [strumento] calcola_rata
[token] input 616, output 79
Per uno smartphone da 899 euro in 30 rate paghi 29,97 euro al mese, senza interessi.
[token] input 720, output 40
    La riga [strumento] dice che il modello ha chiamato la tua funzione. Le righe [token] sono una per ogni chiamata al modello.

    Torna al primo terminale e ferma il server con Ctrl+C.

  6. Pubblica l'agente su AgentCore Runtime.

    agentcore deploy

    Il primo deploy dura da 3 a 5 minuti, perché prepara anche l'account per AWS CDK. Intanto leggi il riquadro qui sotto.

    Cosa crea il deploy

    Il CLI sintetizza lo stack CloudFormation AgentCore-TelcoCare-default e lo crea. Per ora lo stack contiene il Runtime e il suo ruolo IAM di esecuzione, con i permessi per chiamare i modelli Bedrock e scrivere log, trace e metriche. Il CLI attiva anche CloudWatch Transaction Search, che serve per le trace del Lab 6.

    L'account e la regione di destinazione sono in agentcore/aws-targets.json, creato al primo deploy.

    Cosa dovresti vedere 
    deploying AgentCore-TelcoCare-default (usually takes a few minutes)
deployed project 'TelcoCare' to target 'default'

  7. Controlla cosa è stato creato.

    agentcore status --json

    Ogni risorsa ha il suo ARN. L'ID è l'ultima parte dell'ARN. Lo script id.py lo estrae per te, e lo useremo nei prossimi lab.

    python3 ../scripts/id.py runtime

  8. Parla con l'agente pubblicato. Questa volta senza --locale: la richiesta va al Runtime, firmata con le tue credenziali AWS.

    python3 ../scripts/chiedi.py --utente anna --sessione uno "Ciao, mi chiamo Anna e preferisco essere contattata via email."

    Nella stessa sessione chiedi se si ricorda di te.

    python3 ../scripts/chiedi.py --utente anna --sessione uno "Come mi chiamo e come preferisco essere contattata?"

    Ora fai la stessa domanda in una sessione nuova.

    python3 ../scripts/chiedi.py --utente anna --sessione due "Come mi chiamo e come preferisco essere contattata?"
    Cosa dovresti vedere Nella sessione uno l'agente risponde Anna ed email. Nella sessione due non sa chi sei.
    Perché

    Nella sessione uno la microVM è ancora viva e tiene l'agente, con la conversazione, nella memoria del processo. La sessione due gira in un'altra microVM, che non sa nulla della prima.

    Anche la sessione uno prima o poi si chiude, e con lei la conversazione. Per ricordare fra una sessione e l'altra serve AgentCore Memory, che aggiungi nel prossimo lab.

Prova con Kiro

Apri Kiro nella cartella del progetto e chiedigli di aggiungere uno strumento:

kiro-cli chat

In app/agent/main.py aggiungi uno strumento Strands verifica_copertura(comune: str) che risponde "fibra FTTH disponibile" per Milano, Roma e Bari e "solo FTTC" per gli altri comuni. Registralo nella lista tools.

Provalo con agentcore dev --port 8181 e chiedi.py --locale. Se lo tieni, il cp del Lab 3 lo sovrascrive: va bene così.
