Lab 5 · Code Interpreter e Browser

L'agente esegue codice Python in una sandbox e legge pagine web con un browser remoto. Venti minuti.

Concetto: gli strumenti gestiti da AWS

Code Interpreter esegue il codice scritto dal modello in una sandbox isolata gestita da AgentCore, non nel Runtime del tuo agente. Serve per calcoli, statistiche e analisi di dati, dove un modello che fa i conti a mente sbaglia facilmente.

Browser apre un browser in un ambiente isolato gestito da AgentCore. Il tuo codice lo guida da remoto con il protocollo CDP (Chrome DevTools Protocol), qui attraverso la libreria Playwright.

Per entrambi il ruolo del Runtime ha bisogno di permessi IAM specifici, che il CLI non aggiunge da solo. Li aggiungiamo nello stack CDK del progetto.

  1. Copia i due strumenti e il nuovo main.py.

    cp ../risorse/lab5/strumenti_aws.py app/agent/strumenti_aws.py
cp ../risorse/lab5/main.py app/agent/main.py

    strumenti_aws.py contiene due strumenti Strands. esegui_python apre una sessione di Code Interpreter e ci esegue il codice. leggi_pagina_web apre una sessione di Browser, ci si collega con Playwright, carica la pagina e restituisce il testo.

    app/agent/strumenti_aws.py (estratto)
    @tool
def esegui_python(codice: str) -> str:
    """Esegue codice Python in una sandbox isolata (AgentCore Code Interpreter) ..."""
    with code_session(REGION) as client:
        risposta = client.invoke("executeCode", {"code": codice, "language": "python"})
        for evento in risposta["stream"]:
            return json.dumps(evento["result"], ensure_ascii=False)

  2. Aggiungi Playwright alle dipendenze dell'agente.

    (cd app/agent && uv add "playwright>=1.42,<2")

    Serve solo la libreria Python: il browser vero è quello remoto di AgentCore, quindi non installi Chromium.

  3. Dai al Runtime i permessi per Code Interpreter e Browser, sostituendo lo stack CDK del progetto.

    cp ../risorse/lab5/cdk-stack.ts agentcore/cdk/lib/cdk-stack.ts
    agentcore/cdk/lib/cdk-stack.ts (estratto)
    if (props.application.spec.runtimes?.some((r) => r.name === 'agent')) {
  const agent = this.application.runtime('agent');
  agent.grant(
    ['bedrock-agentcore:StartCodeInterpreterSession', 'bedrock-agentcore:InvokeCodeInterpreter', ...],
    [`arn:${this.partition}:bedrock-agentcore:${this.region}:aws:code-interpreter/*`],
  );
  agent.grant(
    ['bedrock-agentcore:StartBrowserSession', 'bedrock-agentcore:ConnectBrowserAutomationStream', ...],
    [`arn:${this.partition}:bedrock-agentcore:${this.region}:aws:browser/*`],
  );
}

    Questo file è il punto in cui aggiungi al progetto le risorse e i permessi che agentcore.json non descrive. Il controllo if serve per la pulizia finale: quando togli il Runtime dal progetto, lo stack non deve più cercarlo.

  4. Pubblica. Ci vogliono circa 3 minuti: il pacchetto è più grande per via di Playwright.

    agentcore deploy

  5. Chiedi un'analisi dei consumi che richiede dei calcoli.

    python3 ../scripts/chiedi.py --utente anna --sessione consumi "Questi sono i miei consumi di dati mobili degli ultimi sei mesi, in GB: maggio 38, giugno 52, luglio 71, agosto 95, settembre 47, ottobre 44. Calcola media, massimo e deviazione standard eseguendo codice Python, poi dimmi se mi basta un piano da 50 GB o se serve quello da 150 GB."
    Cosa dovresti vedere [strumento] esegui_python, poi la media (circa 57,8 GB), il massimo (95 GB, agosto) e la deviazione standard, con un consiglio sul piano. Se nel Lab 2 hai detto all'agente che lavori da remoto, potrebbe tenerne conto.

  6. Chiedi all'agente di leggere una pagina web.

    python3 ../scripts/chiedi.py --utente anna --sessione fibra "Leggi la pagina https://it.wikipedia.org/wiki/Fiber_to_the_x e spiegami in tre frasi la differenza fra FTTC e FTTH."
    Cosa dovresti vedere [strumento] leggi_pagina_web e una spiegazione basata sulla pagina, per esempio che con la FTTC la fibra si ferma all'armadio stradale e l'ultimo tratto è in rame. Nelle nostre prove la risposta è arrivata in circa 20 secondi.
Una trappola che abbiamo trovato

Nel pacchetto CodeZip il programma node che Playwright usa internamente perde il permesso di esecuzione, e lo strumento fallisce con Permission denied: '/var/task/playwright/driver/node'. Per questo strumenti_aws.py ha la funzione _prepara_playwright, che copia il programma in /tmp, lo rende eseguibile e lo indica a Playwright con la variabile PLAYWRIGHT_NODEJS_PATH. Con il deploy a container, che conserva i permessi dei file, non servirebbe: è una nostra deduzione, non l'abbiamo provato.

Il web è un input non fidato

Una pagina web può contenere istruzioni scritte per ingannare il modello. In produzione conviene limitare i siti che l'agente può aprire e non dargli, nella stessa conversazione, strumenti con effetti importanti senza un controllo come la regola Cedar del Lab 4.
